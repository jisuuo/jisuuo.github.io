## 궁금했던 점

존재하지 않는 사용자를 조회하면 당연히 404가 반환될 것이라고 생각했다.

그런데 `RuntimeException`을 발생시키면 왜 404가 아닌 500이 반환되는 걸까?

그리고 RFC에 HTTP 상태 코드가 정의되어 있는데, Spring은 왜 알아서 404를 반환하지 않는 걸까?

## 1. RFC와 Spring의 역할

먼저 두 가지를 구분해야 했다.

- **RFC:** HTTP 상태 코드가 어떤 의미인지 정의한다.
- **Spring:** 실제 코드에서 발생한 상황을 HTTP 응답으로 처리한다.

RFC 9110에서 정의하는 상태 코드의 의미는 다음과 같다.

| 상태 코드 | 의미 |
|---|---|
| 200 | 요청이 성공적으로 처리됨 |
| 404 | 요청한 리소스를 찾지 못했거나 존재를 공개하지 않음 |
| 500 | 서버가 예기치 않은 상황으로 요청 처리에 실패함 |

중요한 것은 **RFC가 Java의 예외를 어떤 HTTP 상태 코드로 변환할지까지 정해주지는 않는다**는 점이다.

## 2. 실제 코드로 이해하기

```java
@GetMapping("/users/{id}")
public String getUser(@PathVariable Long id) {

    if (id == 999) {
        throw new RuntimeException("사용자가 없습니다");
    }

    return "홍길동";
}
```

`GET /users/999` 요청을 보내면 어떻게 될까?

```text
GET /users/999
       ↓
Controller 실행
       ↓
id == 999 → true
       ↓
RuntimeException 발생
       ↓
Spring 예외 처리
       ↓
HTTP 500
```

별도의 예외 처리기가 없는 일반적인 Spring Boot 환경을 가정한 흐름이다.

`RuntimeException`은 Java에서 예외가 발생했다는 뜻일 뿐, HTTP 404로 응답하라는 정보는 없다.

따라서 예외 메시지에 "사용자가 없습니다"라고 적었다고 해서 Spring이 자동으로 404를 반환하지는 않는다.

## 3. 그렇다면 404는 어떻게 반환할까?

```java
throw new ResponseStatusException(
    HttpStatus.NOT_FOUND,
    "사용자가 없습니다"
);
```

이번에는 `HttpStatus.NOT_FOUND`를 명시했다.

Spring이 이 예외를 처리하면서 HTTP 404를 반환하도록 한 것이다.

즉, 같은 사용자 미존재 상황이라도 **개발자가 어떤 예외 처리 정책을 구현했는지에 따라 응답이 달라진다.**

## 4. RFC 위반과 API 계약 위반은 다르다

처음에는 404가 나와야 하는데 500이 나오면 RFC를 지키지 않은 것이라고 생각했다.

하지만 두 가지는 다르다.

- **RFC 스펙:** 404와 500의 의미를 정의한다.
- **API 계약:** 우리 서비스에서 사용자가 없을 때 404를 반환하겠다고 약속한다.
- **구현:** Spring에서 그 약속을 지키도록 코드를 작성한다.
- **검증:** 실제 요청을 보내서 404가 반환되는지 확인한다.

따라서 사용자 조회 API가 404를 반환하기로 약속했는데 500이 나왔다면, 우선 API 계약을 제대로 구현했는지 확인해야 한다.

이 상황만으로 RFC 위반이라고 단정할 수는 없다.

## 정리

이번에 이해한 내용은 다음과 같다.

1. RFC는 HTTP 상태 코드의 의미를 정의한다.
2. Spring은 발생한 예외를 처리해 실제 HTTP 응답을 만든다.
3. Java 예외 메시지만 보고 Spring이 자동으로 HTTP 상태 코드를 결정하는 것은 아니다.
4. API 계약에서 약속한 응답을 반환하도록 개발자가 구현하고 검증해야 한다.

## 다시 생각해 볼 질문

- `RuntimeException`을 발생시키면 왜 자동으로 404가 되지 않을까?
- RFC에서 정의하는 것과 API 계약에서 정의하는 것은 무엇이 다를까?
- 404를 예상했는데 500이 나왔다면 어떤 코드부터 확인해야 할까?

### 느낀 점

이전에는 HTTP 상태 코드가 정해져 있으니 Spring이 상황에 맞게 알아서 반환한다고 막연하게 생각했다.

하지만 RFC에서 규칙을 정의하는 것과 실제 애플리케이션이 그 규칙에 맞춰 응답을 만드는 것은 별개라는 것을 알게 되었다.

앞으로 API를 구현할 때도 정상 응답뿐 아니라 예외 상황에서 어떤 상태 코드를 반환해야 하는지 먼저 정의하고, 실제로 그 계약을 지키는지 확인해야겠다.
